# 按需排查：串口、动作结果与重连

主流程以 [SKILL.md](../SKILL.md) 为准；这里只在用户遇到问题或需要解释结果时查。

- **串口找不到或没权限**：先确认 USB 接稳且选择了正确转接器，用 `ls -l /dev/serial/by-id/` 看稳定路径及对应节点。读命令也要串口读写权限，因为它需发请求，不代表会写配置。请设备管理员只给 Agent 实际运行的 Linux 用户开放当前节点。例：Agent 与操作者是同一账户，且实际解析到 `/dev/ttyACM0`，由用户在自己的终端运行 `sudo setfacl -m "u:$(id -un):rw" /dev/ttyACM0`。不要照抄不匹配的设备，或用 `chmod 777`；重连后 ACL 可能消失。串口被占用请用户关掉相关程序。串口权限正常仍不通，检查供电、线序、当前 ID 和 1 Mbps；不要扫描或猜写。
- **动作超时/保护停止**：现有代码保持步间停稳后等待至少 1 秒、回中总预算 180 秒；等待中仍可能保持扭矩，时限不是限速、物理急停或温升保证。先物理断电，不等待软件来救援；只按主流程的具体条件提供一次人工重试。用实际输出和 `records/` 判读停止阶段及卸力读回；重连后静止不能还原触发瞬间，也不能判定保护误报。
- **复验比对**：按主流程的字段，用动作后的 `final_inspect.snapshot`（仅改号时用 `set-id.snapshot`）对照新 ID 的 `inspect`。已有完整快照才说「17 项不变」；位置、状态单独验收，电压/温度按实读报告。`goal_raw` 是目标读数，不是零位；其变化或未归零既不证明完整断电，也不单独否定掉电保持。若旧 ID 的 PING 不是指定的无应答结果，或已无基线/旧 ID 证据，按缺项如实报告，不补动作、不扫描。
- **版本校验失败**：`C001-RUNTIME.sha256` 随已核实的执行基线提供，覆盖 21 个原有非 README 文件。它不覆盖使用文档和现场 records，也不鉴别第三方发布者。不要现场重算一份清单把改动当正常；恢复可信同版本文件后再处理。`motion-prepare`/`motion-run` 还另行绑定本次工具目录内容和设备节点，但无法识别全部换件、热插拔或断电情形。
